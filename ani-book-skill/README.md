# 网文大纲流程优化实验

本目录是实验控制端。同级项目 `../../ani-book-skill/` 提供创作 Skill、拆书材料和可修改的流程。一次实验固定创作任务、评判标准和裁判型号，先测原流程，再让 Codex 针对低分修改流程。每一轮都有独立 worktree、作品和评判记录，最终由作者选择。此做法借鉴了 autoresearch 的固定基线、独立评测和逐轮结果表。[原项目实验规约](https://github.com/wuwie1/autoresearch/blob/master/program.md)

## 职责与文件

| 职责 | 文件或目录 | 负责的决定 |
| --- | --- | --- |
| 作者定义实验 | [三书玄幻任务](cases/三书玄幻.json) | 目标读者、约 200 万字、固定故事起点、三本书各自承担什么、硬规划到第几卷、开篇做到第几章。可另存任务，用 `--case` 指定。 |
| 制定评分标准 | [rubric.json](rubric.json) | 八个维度分别按 0–100 整数评分，每项达标线 `minimum` 默认为 80 分。带 `evidence` 的维度要求相应处数的引文。调整标准后开一个新实验。 |
| Codex 生成作品 | [生成提示词](prompts/generate.md) | 读取本轮 worktree 的 Skill 和任务登记的拆书报告，其余材料按 Skill 和报告里的链接自取。交付总纲、分卷、开篇章纲、三项机制的来源和原创落点。 |
| Cursor 独立判断 | [裁判提示词](prompts/judge.md) · [终端调用](providers.py) | 通过 `agent --print --trust --mode ask --model …` 调用 Claude Opus 5.5。裁判在只含评判材料的临时目录读取任务、冻结的参考依据、本版引用的拆书原文、量表和匿名作品。返回分项分数、原文引证、理由和作品里最该先补的安排。 |
| Codex 诊断和优化 | [优化提示词](prompts/optimize.md) · [worktree 管理](worktrees.py) | 回查拆书维度遗漏、证据不足、机制未传到卷章等原因。在候选 worktree 提出一项可验证的改动。程序检查并应用补丁、创建本地提交、运行项目验证。 |
| 自动运行和停止 | [run.py](run.py) · [工件和分数校验](assessment.py) | 冻结输入，按“生成→评分→检查门槛→修流程→重新生成”循环。控制端校验分值、引文和总篇幅，并执行次数上限。 |
| 记录与人工选择 | [逐项结果表](results/results.tsv) · `results/<实验编号>/` | 表中每轮每项一行，保存分数、各次评分、门槛、出处、裁判和 Git 提交。每个实验另有可打开的候选对照表、作品、完整评分和选择记录。 |

## 当前任务与量表

《张三丰异界游》承担从个人本领到组织能力的故事框架。《我在精神病院学斩神》提供视角、对白动作、信息差和关照感等写法。《遮天》提供修行代价、世界规则和逐步发现古史的方法。每项参考都要能在已拆材料中核对，再由新人物、新规则和新事件实现。

默认任务交付全书总纲、约 200 万字的分卷预算（允许上下浮动 20 万字）和开篇连续 6 章章纲。前三卷按硬规划交付，其中前两卷写出开卷抓手、首次升级、中点转向、压力锁定、高潮兑现、卷末牵引六个节点，供裁判核对中段的回报。第四卷起只交方向，量表按方向、职责和承诺能否接上前卷来评，与 Skill 的规划深度约定一致。固定的山驿测脉人起点用于跨轮比较，可以在新实验中替换。写法维度评判场景设计能否交给写手执行。

每个维度都有五条可对照作品的描述，依次对应 0–39、40–59、60–79、80–89、90–100 分。每档内按卷章证据和兑现程度取整数。八项均达到各自门槛才通过。例如某项 79 分，其余七项 100 分，即使均分是 97.375 分，只要还有优化次数，流程就继续。

| 维度 | 达到默认 80 分门槛时可看到的证据 |
| --- | --- |
| 卖点与开篇兑现 | 开篇章纲前半就有具体压力引出的主动选择和首个同类回报，结果留下下一问。 |
| 长期冲突与成长循环 | 硬规划的各卷之间有因果，前一轮所得引来新责任或反制，迫使主角换办法。引两处。 |
| 人物主动性与关系代价 | 主角和配角都有别的路可选，选择之后有人承担得失。 |
| 世界规则与历史探索 | 规则既给机会也限制人物，两个阶段的证据改变对世界的理解和行动。 |
| 追读节奏与情绪回报 | 短、中、长线的设问和兑现可定位，相邻回报的种类或代价有别，下一问从上一次回报的后果里来。引两处。 |
| 两百万字分卷与终局 | 各卷有预算，硬规划各卷有独立职责和因果交接，终局方向回应开书愿望并保留代价。引两处。 |
| 场景写法的可执行性 | 至少两处章纲能指认观察者、延迟的信息和改变判断的动作，且效果有别。 |
| 三书分工与原创转化 | 三种机制各有拆书证据和目标卷章，人物、规则与因果都已原创重建。 |

## 怎样读分数

每个版本由裁判独立评 `--judgments` 次，默认两次。每项取各次中的低值，所以一项要每次都达到门槛才算达标。候选对照里的“最大分差”是同一份作品同一项在各次评分间的最大差距，它说明裁判自己的波动有多大。

版本之间只比离门槛的距离：未达标项的差额合计更小的在前，差额相同时未达标项更少的在前。已过门槛的分数再涨不算提升。持平时沿用先前起点。

每个版本只生成一次，生成本身也有波动。正式优化前先测一遍，用不同编号对同一基线各跑一次只评不改的实验：

```sh
python3 ani-book-skill/run.py run --id xuanhuan-base-a --max-optimizations 0
python3 ani-book-skill/run.py run --id xuanhuan-base-b --max-optimizations 0
python3 ani-book-skill/run.py run --id xuanhuan-base-c --max-optimizations 0
```

在 `results/results.tsv` 里比较三次的同一维度。三次里时过时不过的维度，单次实验的提分不足为凭。候选选定后，可以用 `--base codex/ani-eval/<编号>/rNNN --max-optimizations 0` 对它再采样，也可以另写一份任务文件作留出复验。同一个提交无论作基线还是作候选，拿到的生成提示词相同。

## 运行

以下命令在 `autocommand/` 根目录执行。需要 Python 3.10+、Git、已登录的 Codex CLI 和 Cursor CLI `agent`，两个 CLI 都要在 PATH 里。进程锁与进程超时处理支持 macOS、Linux。本地 `check` 只读指定 Git 版本的资料，查找两个 CLI 的路径。

```sh
python3 ani-book-skill/run.py check
```

正式启动时指定一个实验编号和最多优化次数。下面的 `2` 指基线之后最多改两次流程，最多生成和评判三个版本。`0` 表示只评一次基线。基线若已达标就直接停止。缺少 CLI 时不建立实验。

```sh
python3 ani-book-skill/run.py run --id xuanhuan-01 --max-optimizations 2 --timeout 2400
```

`--project` 可以指向其他目标工作副本，`--base` 默认为目标仓当前 HEAD 提交。实验从已提交版本创建 worktree，本地待提交的稿件可继续在原工作副本中编辑。每个 worktree 是目标仓的一份完整检出。`--timeout` 控制单次调用的秒数，默认 900，推理强度高时宜放宽，`resume` 时可以用 `--timeout` 改。

生成端在启动时定下来。`--generator-model` 指定 Codex 模型，省略时取本机 Codex 配置里的模型和推理强度。实际取值连同 CLI 版本写入 `run.json` 的 `generator`，此后每一轮都按它调用。Cursor 优先使用账户列出的 `claude-opus-5-5`，仅列分档型号时选择同系列 `claude-opus-5-5-medium`，实际传入的 ID 写入报告。控制端四个 Python 文件的指纹记在 `run.json` 的 `control`，每轮记下评分时所用的那一版。

每个可评分版本都会生成三份 Markdown 和一份 `引用依据.md`。后者列出规划引用的拆书段落，并标明该句在冻结的基线材料里是否已有，裁判读到的是同一份。`judgment-N.json` 是各次评分，`score.json` 是合并结果，`judge-raw/` 保存裁判每次的原始回答，包括未通过校验的。优化轮还会留下问题诊断、被验证的修改假设、补丁建议和验证日志。源代码提交位于目标仓的 `codex/ani-eval/<编号>/rNNN` 分支，工作树位于本目录的 `.worktrees/<编号>/round-NNN/`，目录被删后 `resume` 会从分支重新检出。

优化器可以改 `SKILL.md`、`references`、`scripts`、`agents`、`assets`，以及任务所列书目的 `pattern-cards` 和 `sections`。阅读笔记、覆盖图、状态文件和现有测试保持原样，测试可以新增。在 `references` 或拆书目录新建的文件要在同一提议里由已有文件链接。

| 运行结果 | 如何接续 |
| --- | --- |
| `qualified` | 全部分项达标，停止自动优化，查看候选对照。 |
| `limit_reached` | 已用完指定优化次数。未达标项保留在结果里，进入人工选择。 |
| 候选验证失败 `invalid` | 目标项目的检查未通过，或检查在工作树留下了文件。保存该 worktree 和日志，消耗一次优化机会。有剩余次数时从此前最接近达标的版本另试。 |
| 运行错误 `error` | 保留已完成阶段。登录、网络、无效引文、无法应用的补丁等会留下原因。修复后用 `resume` 接续，已生成的规划和已完成的评分可继续使用。 |

```sh
python3 ani-book-skill/run.py resume xuanhuan-01
```

## 人工选版

打开 `results/<编号>/候选对照.md`，逐轮查看起点、书稿、各项分数与候选提交。“起点”一列写明该轮在哪一轮的提交上修改，起点是第 0 轮的候选只含自己的一处改动。分项详情在 `round-NNN/score.json`，原始创作任务与标准在 `inputs/`，低分修订依据在下一候选的 `proposal.json`。可以选择任一已评分轮，包括基线与自动比较中排名较低的版本。`qualified` 只表示各项过线，过线版本的均分可能低于基线，选版前对照两者的均分和正文。

```sh
python3 ani-book-skill/run.py select xuanhuan-01 1 --note "保留这一版的第二卷反转"
git -C ../ani-book-skill show codex/ani-eval/xuanhuan-01/r001
```

`select` 把人工选择写进 `run.json` 和候选对照。向目标主分支合入以及更新已安装的创作技能，留给作者选定版本后的独立操作。裁判运行的 Cursor 环境能看到已安装的技能，副本改变后，后续实验先重评基线。

在临时仓库中验证循环可运行以下测试。测试用本地替身代替两个模型 CLI。

```sh
python3 -B -m unittest discover -s ani-book-skill/tests -v
```
