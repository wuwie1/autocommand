# autocommand

在这里用书名和目标发起跨项目创作任务。`ani-book-skill` 把参考书拆成可追溯的写作机制，据此设计和调优原创小说。`assistant` 接收选定的大纲修订，在 Web 工作台生成具体章节。三个仓库按同级目录放置。

查参考书时可以指定书名，也可以按题材或写作问题从已有分析中选书。接续原创时，把示例中的《目标书名》换成你要处理的作品。

| 想做的事 | 可以这样说 | 直接入口 |
| --- | --- | --- |
| 查已有拆书 | “从当前已完成的拆书分析中，找出两种让主角主动推动情节的机制，注明参考书、证据和适用条件。” | [查机制卡与证据](docs/book-workspaces.md#查拆书资料) |
| 从参考书开新项目 | “从已有分析中挑选适合参考势力成长和信息差写法的作品，设计一部原创都市小说。这轮先给我两个方向，选定后再做分卷大纲。” | [机制迁移方法](../ani-book-skill/references/analysis-to-novel.md) |
| 查看已有作品 | “列出已有本地规划的原创作品，以及在目标 Web 环境中已经生成正文的作品，注明各自进度。” | [本地规划](docs/book-workspaces.md#查原创规划) · [Web 作品](docs/web-handoff.md#功能与路径) |
| 调优原创规划 | “检查《目标书名》第一卷前三章。对照写作风格和首卷细纲，标出读者回报落空的地方，先给修改建议。” | [定位有效卷纲和章计划](docs/book-workspaces.md#查原创规划) |
| 自动优化大纲生成流程 | “用三本拆书成果生成约 200 万字的玄幻规划，让 Cursor Opus 独立打分，最多优化两次，保留所有候选给我选。” | [实验职责、量表与运行方式](ani-book-skill/README.md) |
| 准备 Web 交接 | “把《目标书名》已定的总纲、分卷和前三章整理成可导入的大纲，列出需要我选定的内容。这次做到交接稿。” | [交接材料对照](docs/web-handoff.md#整理本次采用的材料) |
| 在 Web 写章 | “在 Web 继续《目标书名》，核对绑定的大纲修订，按已选定的首章计划生成第 1 章，给我章节入口和审校结果。” | [章节功能与路径](docs/web-handoff.md#功能与路径) · [单章审校依据](docs/evaluation.md#查单章审校) |

跨仓职责与接续约定见 [AGENTS.md](AGENTS.md)。大纲流程实验与 Web 成稿实验的入口见[评判与实验说明](docs/evaluation.md)。
