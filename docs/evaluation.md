# 网文评分与自动调优草案

本仓的跨版本自动评测处于设计阶段。后续要回答的是，在同一组写作任务上，哪一项规划或写法调整能稳定改善成稿。实验采用固定样本和预算、先跑基线、记录每次结果、保留有效改动的做法。[autoresearch](https://github.com/karpathy/autoresearch) · [上游实验说明](https://github.com/karpathy/autoresearch/blob/master/program.md)

## 查单章审校

查“这一章为什么得这个分”时，从[目标章节和运行记录](web-handoff.md#功能与路径)定位本次审校结果，核对具体问题的正文证据。Web 现有分项包括连贯性、重复、节奏、声音、吸引力及综合分。要核对字段查评分结构，要追溯评估过程查审校服务。[Web 评分字段](../../assistant/shared/types/chapterRuntime/qualitySchemas.ts) · [章节审校服务](../../assistant/server/src/services/novel/runtime/ChapterAcceptanceAssessmentService.ts)

核对本章承诺的回报、关键转折、章末净变化和继承的钩子时，读本章读者体验合同。接收、修复、继续或暂停由 Web 任务策略决定。下文的跨版本实验使用自己的量表，并保留单章审校的原始证据。[读者体验合同](../../assistant/docs/wiki/workflows/reader-experience-contract.md) · [章节生产链](../../assistant/docs/wiki/workflows/chapter-production-chain.md)

## 首版候选维度

| 维度 | 在正文中查什么 |
| --- | --- |
| 承接与追读 | 上章留下的问题如何落到本章行动，章末发生了什么，让读者想看下一章？首章看开篇提出的问题 |
| 人物动机与主动性 | 谁在什么压力下做了选择，这个选择怎样改变结果？ |
| 冲突与节奏 | 阻力是否推动局面变化，哪些段落在重复同一信息或拖延行动？ |
| 爽点与情绪兑现 | 本章答应给目标读者什么，他们在哪个动作、结果或关系变化里得到回报？ |
| 设定与连续性 | 对照已发生事实、人物知情边界和伏笔计划，有无矛盾或提前揭晓？ |
| 文风与可读性 | 对白能否分辨人物，视角和叙述是否清楚，文字是否符合本书写法约定？ |

建议起始量表为每项 1–5 分。1 分表示关键效果缺失或与证据冲突，3 分表示能定位到效果但执行有缺口，5 分表示按本章职责充分实现。每项附章号、段落位置及判断理由。先按章计划判断应交付的回报强度，铺垫章也可以获得满分。样本缺正文或关键上下文时记“资料不足”，补齐后再比较。

## 一轮实验怎么做

1. **冻结基线。** 选有代表性的开篇、过渡、兑现章节，保存现行规划、必要前文、生成设置、评审模型与量表版本、每组预算和复跑次数。留出一组同类章节复验。按现行规划先跑基线，记录每章的分数和证据。
2. **只改一个因素。** 例如只改候选章纲里“主角要做的选择”，记录预期改善的维度。两组都从相同的前文状态开始，使用相同设置和预算，在 Web 的实验用作品中生成正文。
3. **成对评审。** 隐去版本名，对同一章的两稿分别打分，逐项写出差异证据。初版建议各维度等权，先算每章均分，再对相同章组求均值。评审缺失或运行失败单列并保留原因，待补跑齐后再比较。
4. **决定是否更新。** 候选均分提升、留出样本复验支持改善，且遵守硬设定和人物知情边界时，将该改动保留为下一轮实验基线。持平、退化或违反硬设定时沿用原基线。复跑判断分歧时记“待复核”。采用到正式作品时，按所属仓库的规划修订或 Web 交接流程处理。
5. **留下可复查的记录。** 每轮保存样本与范围、来源版本、基线与候选标识、唯一改动、生成与评审设置、预算与实际用量、分项得分、证据位置、复验结果和保留决定。达到本轮预算或预定轮数后汇总。更改量表或评审模型时另建基线。

首个可验证的实现是用同一章的一对草稿产出完整评分记录，再用一组留出章节验证“保留、舍弃、待复核”的决定。自动更新的对象先限定为实验中的规划或写法版本。
