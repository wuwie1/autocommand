# 网文大纲评判与成稿实验

开写前的大纲流程实验位于本仓的 `ani-book-skill/`。Codex 从目标仓的指定版本生成规划，Cursor Opus 按冻结量表独立评判八个维度，每项满分 100 分。每个版本默认独立评两次，各项取低值，每项达到 80 分才通过。低分触发独立 worktree 上的流程修订，全部达标或用完次数后由作者选版。[职责与命令](../ani-book-skill/README.md) · [逐项标准](../ani-book-skill/rubric.json) · [评分记录](../ani-book-skill/results/results.tsv)

以下 Web 成稿的跨版本实验处于设计阶段。后续要回答的是，在同一组写作任务上，哪一项规划或写法调整能稳定改善成稿。实验采用固定样本和预算、先跑基线、记录每次结果、保留有效改动的做法。[参考实验规约](https://github.com/wuwie1/autoresearch/blob/master/program.md)

## 查单章审校

查“这一章为什么得这个分”时，从[目标章节和运行记录](web-handoff.md#功能与路径)定位本次审校结果，核对具体问题的正文证据。Web 现有分项包括连贯性、重复、节奏、声音、吸引力及综合分。要核对字段查评分结构，要追溯评估过程查审校服务。[Web 评分字段](../../assistant/shared/types/chapterRuntime/qualitySchemas.ts) · [章节审校服务](../../assistant/server/src/services/novel/runtime/ChapterAcceptanceAssessmentService.ts)

核对本章承诺的回报、关键转折、章末净变化和继承的钩子时，读本章读者体验合同。接收、修复、继续或暂停由 Web 任务策略决定。下文的跨版本实验使用自己的量表，并保留单章审校的原始证据。[读者体验合同](../../assistant/docs/wiki/workflows/reader-experience-contract.md) · [章节生产链](../../assistant/docs/wiki/workflows/chapter-production-chain.md)

## 成稿实验的候选维度

| 维度 | 在正文中查什么 |
| --- | --- |
| 承接与追读 | 上章留下的问题如何落到本章行动，章末发生了什么，让读者想看下一章？首章看开篇提出的问题 |
| 人物动机与主动性 | 谁在什么压力下做了选择，这个选择怎样改变结果？ |
| 冲突与节奏 | 阻力是否推动局面变化，哪些段落在重复同一信息或拖延行动？ |
| 爽点与情绪兑现 | 本章答应给目标读者什么，他们在哪个动作、结果或关系变化里得到回报？ |
| 设定与连续性 | 对照已发生事实、人物知情边界和伏笔计划，有无矛盾或提前揭晓？ |
| 文风与可读性 | 对白能否分辨人物，视角和叙述是否清楚，文字是否符合本书写法约定？ |

成稿对照实验建议每项记 0–100 整数分。0–39 分表示关键效果缺失或与证据冲突，40–59 分表示写出了尝试但读者回报尚不清楚，60–79 分表示效果可定位但执行有缺口，80–89 分表示兑现了本章承诺，90–100 分表示承诺充分兑现且与前后情节衔接紧密。每项附章号、段落位置及判断理由。先按章计划判断应交付的回报强度，铺垫章也可以获得满分。样本缺正文或关键上下文时记“资料不足”，补齐后再比较。

## 一轮实验怎么做

1. **冻结基线。** 选有代表性的开篇、过渡、兑现章节，保存现行规划、必要前文、生成设置、评审模型与量表版本、每组预算和复跑次数。留出一组同类章节复验。按现行规划先跑基线，记录每章的分数和证据。
2. **只改一个因素。** 例如只改候选章纲里“主角要做的选择”，记录预期改善的维度。两组都从相同的前文状态开始，使用相同设置和预算，在 Web 的实验用作品中生成正文。
3. **成对评审。** 隐去版本名，对同一章的两稿分别打分，逐项写出差异证据。初版建议各维度等权，先算每章均分，再对相同章组求均值。评审缺失或运行失败单列并保留原因，待补跑齐后再比较。
4. **决定是否更新。** 候选均分提升、留出样本复验支持改善，且遵守硬设定和人物知情边界时，将该改动保留为下一轮实验基线。持平、退化或违反硬设定时沿用原基线。复跑判断分歧时记“待复核”。采用到正式作品时，按所属仓库的规划修订或 Web 交接流程处理。
5. **留下可复查的记录。** 每轮保存样本与范围、来源版本、基线与候选标识、唯一改动、生成与评审设置、预算与实际用量、分项得分、证据位置、复验结果和保留决定。达到本轮预算或预定轮数后汇总。更改量表或评审模型时另建基线。

成稿实验的首个验证目标是用同一章的一对草稿产出完整评分记录，再用一组留出章节验证“保留、舍弃、待复核”的决定。自动更新的对象先限定为实验中的规划或写法版本。

## 正文提示词优化实施计划

首轮固定章纲、前情和模型，验证一条写法要求能否让读者更清楚地感受到人物的选择和代价。建议由 `assistant` 提供真实写章输入、提示词渲染和试写，本仓在拟建的 `chapter-writer/` 管理样本、候选、独立评分及对照记录。

正文效果实验室已支持用未保存的写法试写。普通预览从所选书、章组装材料时，会将前章摘要和章尾初始化为空。正式写章组装器会读取前一章正文。因此，第一步是比较两边实际送给模型的内容。启用新生产内核的作品可复用注册 Writer 已有的请求和指纹。[实验室用法](../../assistant/mintlify-docs/features/prompt-management.mdx) · [预览组装](../../assistant/server/src/prompting/workbench/writerPreviewContext.ts) · [正式组装](../../assistant/server/src/services/novel/runtime/GenerationContextAssembler.ts) · [内核 Writer](../../assistant/server/src/modules/production/infrastructure/services/registeredWriter.ts)

### 先用一章跑通

建议用《借山一步》第 4 章《那盏灯是给井下的》。第 3 章结尾，梁穗以为亮灯意味着有人要坐车。第 4 章先让读者看见石桂举灯叫井里的徒弟。梁照仍以为她在等车，直到看见徒弟湿到膝头的裤腿，才压住缰绳，放过一次合坡。评审可以指出读者何时明白、梁照何时明白，以及他的选择究竟损失了什么。本仓已有开篇六章的章纲，入组前还要核对实验作品的修订和第 3 章实际正文。若尚无写前材料，可先用已有完整输入的章节验证工具。[第 3、4 章原始章纲](../ani-book-skill/results/xuanhuan-20261126-190108/round-000/开篇章纲.md)

A 使用本书实际生效的正文提示词。B 只改 `writer.antiAiRules`，例如“人物改变判断时，先让读者看到他眼前出现的新证据，再用他的下一个动作写出这个变化”。这条候选规则应能用到别章。预览两份最终消息，确认差异只落在这条规则上，再花额度试写。[正文提示词及可调字段](../../assistant/server/src/prompting/prompts/novel/chapterWriter.prompts.ts)

### 实现顺序与验收

| 交付 | 做法 | 验收依据 |
| --- | --- | --- |
| 1. 一份可重放的写前快照 | 在目标书实际使用的正式 Writer 路径，取模型调用前的章节任务、读者回报、前章正文、人物硬事实与知情边界、伏笔指令和写法。保存章节与大纲修订标识、有效模板与槽位、选入或裁剪的材料、顺序和内容指纹，以及实际模型、温度、推理设置和输入输出预算。历史章节取当时的写前状态。 | 用冻结材料和原提示词重渲染，逐条比对正式请求的消息角色、顺序和内容。核对实际生效的模型参数。目标章成稿、事后审校和未来正文不得泄入样本。 |
| 2. 同章生成两份初稿 | 复用正文效果实验室的草稿覆盖和试写服务，A、B 从同一快照生成。若现有试写入口仍会读取实时资料，在 `assistant` 给注册 Writer 补最小的冻结材料重放能力。 | 两稿上下文指纹一致，最终消息只有预定差异。保存两份初稿、实际用量和耗时，核对实验前后的正式章节正文、状态和生效模板版本一致。 |
| 3. 产出一张独立盲评表 | 本仓沿用大纲实验的 Cursor 独立裁判调用。裁判只看匿名初稿、同份写前事实、章节目标与量表。随机安排左右稿，再交换顺序独立评一次。 | 每次交付分项分数、胜平负及理由，每处引文能按章号和段落在对应草稿中找到。缺资料、调用失败和换序后结论相反分别记录。 |
| 4. 按结果迭代 | 先在讨论中根据开发样本的低分段落拟一条候选写法，自动化后可由 Codex 提议。用原提示词重复生成，估计基线波动，再在相同设置和预算下复测候选。启动时限定轮数和总用量，重试从缺失步骤接续。 | 保留每轮提示词差异、逐章分差、用量、失败原因和取舍。达到预算即汇总，候选通过独立复验后由作者决定是否应用到本书。 |

第一个可交付版本做到第 3 步即可。现有 `POST /api/prompt-workbench/test-run` 接受请求级 `slotOverrides` 或 `templateDraft`，能返回正文、最终消息、上下文、实际模型和可用的用量记录。先对齐输入，再复用这个入口完成两次试写和两次换序盲评，输出可重放的请求、两份原稿和一张有引文的对照表。[试写接口](../../assistant/server/src/routes/promptWorkbench.ts) · [试写服务](../../assistant/server/src/prompting/PromptWorkbenchService.ts) · [现有裁判调用](../ani-book-skill/providers.py)

### 怎么判断值得采用

- **首轮量表**建议用 100 分衡量正文写法，表达自然度和情绪感染力各 20 分，剧情推进与节奏、人物与对白各 15 分，章纲执行、逻辑与一致性、追读意愿各 10 分。铺垫章按它承诺的小回报评分。权重在生成前冻结，Web 审校结果可以附作证据。
- **先看硬伤。** 要求裁判引用写前依据与正文原句，标明严重设定矛盾、越过人物知情边界、提前揭底或漏掉本章关键选择。候选出现经复核的硬伤即淘汰。材料缺失导致无法判断的样本记为“资料不足”。
- **再看改善能否复现。** 单章只验证流程。调优样本覆盖开篇、过渡与兑现，另留从未交给优化器的章节。按章比较加权分差和胜平负。改善超过基线重复生成的波动、在留出样本上同向，才进入连写复验。连写建议先做三章，两组从同一前情开始，后两章各继承本组上一章正文及其状态，检查人物知道什么、旧钩子如何承接和兑现。分歧留待复核。
- **按证据选下一轮。** 同类章节反复出现表达问题，再试章节类型写法。关键旧事未进入实际消息，就固定提示词，先比较上下文取舍，另轮再调输入预算。章纲本身缺转折时回规划端调整分镜。初稿达标后再对照修文前后效果，长篇验证扩到中后段人物回归和跨卷伏笔回收。
